## Blocking Review Findings

1. Account snapshot encoding accepts internally inconsistent binding digests,
   endpoint/protocol shapes, state combinations, duplicate cleanup IDs, and
   credential transitions. The test fixture itself round-trips invalid
   credential set/delete snapshots instead of proving the account-config
   lifecycle.
2. Generation and trust-epoch checks use saturating addition, allowing
   `u64::MAX -> u64::MAX` to pass an exact-increment rule.
3. Bounded remote-value/capability structs expose public fields and derived
   deserialization that bypass constructors; their schema also uses `usize`
   for `original_bytes`, `sha256` instead of canonical `source_sha256`, and
   does not canonicalize known capability order.
4. The lexical preflight does not apply the 1,024-character first-boundary
   limit to search `from`/`to` strings.
5. The governed operation projection keeps an arbitrary String operation ID,
   despite the new stable `OperationId` contract.

These findings are within the confirmed T201 contract and require a scoped
test-first A003 fix rather than a product/spec expansion.
